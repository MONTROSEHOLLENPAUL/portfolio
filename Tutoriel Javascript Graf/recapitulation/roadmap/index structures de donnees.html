Structures de données

Une structure de données est un format permettant d’organiser, de gérer et de stocker des données de manière à permettre un accès et une modification efficaces. JavaScript a des structures de données primitives (intégrées) et non primitives (non intégrées). Les structures de données primitives sont fournies par défaut avec le langage de programmation et vous pouvez les implémenter prêtes à l’emploi (comme les tableaux et les objets). Les structures de données non primitives ne sont pas fournies par défaut et vous devez les coder si vous voulez les utiliser.

Collections indexées

Les collections indexées sont des collections qui ont des indices numériques, c’est-à-dire des ensembles de données qui sont triés par une valeur d’indice. En JavaScript, un tableau est une collection indexée. Un tableau est un ensemble ordonné de valeurs qui possède un index numérique.

Tableaux

Les tableaux sont des objets qui stockent une collection d’éléments et peuvent être affectés à une variable. Ils ont leurs méthodes qui peuvent effectuer des opérations sur le tableau.

Données structurées

Les données structurées sont utilisées par les moteurs de recherche, comme Google, pour comprendre le contenu de la page, ainsi que pour recueillir des informations sur le Web et le monde en général.
Il est également codé à l’aide d’un balisage dans la page à laquelle les informations s’appliquent.

JSON

JavaScript Object Notation (JSON) est un format texte standard permettant de représenter des données structurées basées sur la syntaxe d’objet JavaScript. Il est couramment utilisé pour transmettre des données dans des applications Web (par exemple, envoyer certaines données du serveur au client, afin qu’elles puissent être affichées sur une page Web, ou vice versa).
Comme décrit ci-dessus, JSON est une chaîne dont le format ressemble beaucoup au format littéral d’objet JavaScript. Vous pouvez inclure les mêmes types de données de base dans JSON que dans un objet JavaScript standard : chaînes, nombres, tableaux, booléens et autres littéraux d’objet. Cela vous permet de construire une hiérarchie de données

Collections à clé

Les collections à clé sont des collections de données qui sont triées par clé et non par index. Ils sont de nature associative. Les objets map et set sont des collections à clé et peuvent être itérés dans l’ordre d’insertion.

Map vs. Object: When should you use them?

Map has characteristics of both object and array. However, Map is more like an object than array due to the nature of storing data in the key-value format.
The similarity with objects ends here though. As you've seen, Map is different in a lot of ways. So, which one should you use, and when? How do you decide?
Use Map when:
Your needs are not that simple. You may want to create keys that are non-strings. Storing an object as a key is a very powerful approach. Map gives you this ability by default.
You need a data structure where elements can be ordered. Regular objects do not maintain the order of their entries.
You are looking for flexibility without relying on an external library like lodash. You may end up using a library like lodash because we do not find methods like has(), values(), delete(), or a property like size with a regular object. Map makes this easy for you by providing all these methods by default.
Use an object when:
You do not have any of the needs listed above.
You rely on JSON.parse() as a Map cannot be parsed with it.

Sets and Arrays in JavaScript

An array, like a Set, allows you to add and remove elements. But Set is quite different, and is not meant to replace arrays.
The major difference between an array and a Set is that arrays allow you to have duplicate elements. Also, some of the Set operations like delete() are faster than array operations like shift() or splice().
Think of Set as an extension of a regular array, just with more muscles. The Set data structure is not a replacement of the array. Both can solve interesting problems.
